# ShotBalance

DaVinci Resolve 에서 그룹으로 묶은 컷들의 노출, 화이트밸런스, 블랙, 채도를 기준 컷에 맞춰 주는 샷 밸런싱 도구입니다.
"정노출"을 정하지 않습니다. 의도는 사람이 기준 컷과 버튼으로 정하고, 앱은 그룹 안의 일관성만 맞춥니다.

버전 0.2.

## 무엇을 하나

**노출과 화이트밸런스**

- 같은 인물의 스킨끼리 비교해서 컷마다 필요한 노출(스톱)과 화이트밸런스 게인을 구합니다.
- 기준 컷에 없는 인물만 나오는 컷은, 두 인물이 함께 나온 컷을 다리 삼아 이어 붙입니다.
- 얼굴이 없는 컷(인서트)은 이미 맞춰진 컷들의 밝기 분포와 중성색에 맞춥니다. 확신이 낮으면 값을 제안만 하고 적용하지 않습니다.
- 플리커, 출렁임, 스트로브, 컷 안 노출 변화를 구분해서 컷 하나에 대표값 하나를 씁니다. 키프레임은 만들지 않습니다.

**블랙/헤이즈**

- 헤이즈나 플레어로 뜬 블랙은 선형 공간에서 더해진 빛이라 게인으로는 못 맞춥니다. 컷마다 게인과 선형 오프셋 두 값(`L' = a·L + o`)을 구해서, 블랙 플로어는 기준 컷의 플로어로 보내고 노출을 맞춘 지점(스킨)은 그대로 둡니다.
- 플로어가 진짜 블랙인지, 화면에 블랙이 없어서 어두운 피사체가 잡힌 것인지는 한 컷만 봐서는 알 수 없습니다. 그래서 양쪽 컷 모두 블랙이 면으로 깔려 있고 스킨으로 이어진 컷일 때만 적용하고, 나머지는 제안으로 둡니다. 오른쪽 패널의 블랙 스위치로 컷마다 켜고 끕니다.
- 블랙은 Linear Gain 방식에서만 동작합니다.

**채도와 밀도**

- 카메라(색 과학)마다 다른 채도를 카메라 단위로 한 값으로 맞춥니다. 재는 양은 같은 인물의 스킨 색도와 배경색 색도 사이의 거리입니다. 이 거리는 화이트밸런스와 노출에 무관하고 채도에 비례합니다.
- 카메라 구분: 파일에서 읽히는 단서(입력 색공간, 해상도, 코덱, 비트 수, 릴 이름의 카메라 글자)가 다르면 다른 카메라로 봅니다. 단서가 전부 같으면(변환본, 메타데이터 없음) 채도 추정값이 두 무리로 갈릴 때만 나눕니다.
- 한 카메라에서 잰 컷이 둘 이상이고 값이 서로 맞을 때만 적용합니다. 컷이 하나뿐이면 제안만 합니다. 배경이 일정하지 않은 세트(LED 조명 등)에서는 재지 않습니다.
- 채도 연산은 채도를 바꿀 때 진한 색의 밝기가 어디로 가는지(밀도)를 함께 정합니다. 기본값은 밝기를 그대로 두는 쪽이고, 설정에서 일반 채도(색이 밝아짐), 조금 진하게, 진하게 중에 고를 수 있습니다.
- 그룹이나 컷의 채도를 버튼으로 올리고 내릴 수 있습니다 (`[` `]`, 한 번에 5%).

**작업 흐름**

- 값은 층으로 저장합니다: `최종 = 자동 매칭값 + 그룹 의도 + 컷 의도`. 노출 버튼 한 번은 1/3 스톱(Shift 1/10, Ctrl 1)입니다.
- 경계 리뷰(`B`): 같은 그룹 안에서 이어지는 컷의 끝 프레임과 첫 프레임을 나란히 보여 줍니다. 좌우 키로 경계를 넘기고, 고른 쪽 컷을 그 자리에서 조정합니다. "확인할 곳부터"로 정렬하면 제안값, 입력 색공간 경고, 플리커가 낀 경계가 앞에 옵니다. 경계를 고르면 Resolve 재생헤드가 컷이 바뀌는 프레임으로 갑니다.
- 값은 타임라인 위치가 아니라 소스(파일명과 소스 프레임 범위) 기준으로 저장합니다. 재편집해도 값이 따라옵니다. 설정의 "다른 타임라인에 같은 값 쓰기"로 티저나 다른 버전 타임라인에 같은 값을 복사합니다.
- 입력 색공간이 신호와 맞지 않는 컷을 표시합니다(예: Rec.709 소스에 S-Log3 지정).
- 컷 잠금, 매칭 제외, 되돌리기를 지원합니다.

## 실행

### exe (권장)

GitHub Actions 가 main 에 푸시할 때마다 Windows 에서 테스트를 돌리고 `ShotBalance.exe` 를 빌드합니다 (Actions 탭의 실행 기록에서 `ShotBalance-windows` 를 내려받습니다). 태그(`v0.2.0` 등)를 푸시하면 같은 exe 를 릴리스에 붙입니다.
직접 빌드하려면 `build_exe.bat` 을 실행합니다. `dist\ShotBalance.exe` 하나가 만들어지고, 파이썬이 없는 PC 에서도 실행됩니다.

### 소스로 실행

- Windows: `ShotBalance.bat` 더블클릭. 처음 한 번 `.venv` 를 만들고 필요한 패키지와 얼굴 모델을 받습니다.
- Resolve 없이 둘러보기: `ShotBalance_demo.bat`
- macOS: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt && .venv/bin/python tools/get_models.py && .venv/bin/python -m balance`

Python 은 3.10 에서 3.12 (64비트)를 권장합니다. Resolve 의 스크립팅 모듈이 이 범위에서 가장 안정적입니다.
창은 설치돼 있는 Edge 또는 Chrome 을 앱 모드로 띄웁니다. 창을 닫으면 앱도 끝납니다.

## Resolve 쪽 준비

1. DaVinci Resolve Studio 를 실행합니다. 환경설정 > 시스템 > 일반에서 "외부 스크립트 사용"을 "로컬"로 바꿉니다.
2. 프로젝트 설정 > 컬러 매니지먼트에서 타임라인 색공간이 **DaVinci WG/Intermediate** 인지 확인합니다. 새 프로젝트의 기본값은 Rec.709 Gamma 2.4 입니다. 다르면 앱이 경고를 띄웁니다.
3. 컬러 페이지에서 입력 변환(CST 노드 또는 컬러 매니지먼트) 바로 다음에 노드를 하나 만들고 라벨을 `EXPOSURE` 로 바꿉니다.
4. 그 노드를 우클릭해 Gamma 를 Linear 로 바꾸고, 프라이머리 팔레트에서 **Lum Mix 를 0** 으로 둡니다.
5. 채도까지 맞추려면 바로 다음에 노드를 하나 더 만들고 라벨을 `MATCH` 로 바꿉니다. 이 노드의 Gamma 는 그대로 둡니다.
6. 이 노드 구성을 모든 컷에 복사합니다.

Resolve 의 스크립팅 API 는 노드를 만들거나 Gamma 를 바꾸는 기능이 없어서 3~6번은 직접 해야 합니다.
두 노드는 ShotBalance 전용으로 두세요. 값을 쓸 때마다 덮어씁니다.

| 노드 | 앱이 쓰는 것 | 담는 값 |
|---|---|---|
| `EXPOSURE` (Gamma=Linear) | `SetCDL` 의 Slope 와 Offset | 노출, 화이트밸런스, 블랙 |
| `MATCH` | `SetLUT` | 채도와 밀도 |

Gamma 를 Linear 로 두는 이유: 노출은 선형 공간의 곱셈이기 때문입니다. DI 타임라인의 Offset 도 비슷하게 동작하지만 `(L + 0.0075)` 에 대한 게인이라 섀도에서 어긋납니다(미드그레이에서 1스톱이 0.0733 이 아니라 0.0712, 블랙은 뜹니다). 설정에서 Offset 방식으로 바꿀 수 있지만 그때는 블랙 매칭을 쓰지 못합니다.
Lum Mix 를 0 으로 두는 이유: 0 이 아니면 Resolve 가 휘도를 유지하려고 다른 채널을 함께 움직여서 채널별 게인이 계산한 값 그대로 들어가지 않습니다.

채도 LUT 는 Resolve 의 LUT 폴더 아래 `ShotBalance` 폴더에 만듭니다 (Windows: `C:\ProgramData\Blackmagic Design\DaVinci Resolve\Support\LUT\ShotBalance`). `SetLUT` 이 이 폴더 밖의 파일은 받지 않기 때문입니다. 파일은 컷마다 만들지 않고 (채도, 밀도) 값마다 하나씩 만들어 함께 씁니다. 이름이 곧 내용입니다: `SB_sat116_den075.cube` 는 채도 116%, 밀도 0.75. 프로젝트를 다른 PC 로 옮길 때는 이 폴더를 같이 옮기면 됩니다.

## 쓰는 순서

1. 앱을 띄우면 현재 타임라인의 컷이 썸네일로 나옵니다.
2. 컷을 골라 `G` 로 그룹을 만들거나, 왼쪽 그룹으로 끌어다 놓습니다. Resolve 의 그룹을 가져올 수도 있습니다(설정).
3. 그룹에서 기준이 될 컷을 고르고 `R` 을 누릅니다. 기준 컷이 없으면 그룹 중앙값에 맞춥니다.
4. "자동 매칭"을 누릅니다. 분석이 끝나면 값이 EXPOSURE 노드와 MATCH 노드에 들어갑니다.
5. 컷 또는 그룹 전체를 고르고 `↑` `↓` 로 의도를 더합니다. 노란 고리가 붙은 컷은 확신이 낮아 적용하지 않은 제안값입니다. 오른쪽 패널에서 켤 수 있습니다.
6. `B` 로 경계 리뷰에 들어가 컷이 바뀌는 지점을 확인합니다.

`\` 를 누르고 있으면 촬영본 그대로를 보여 줍니다. `?` 로 단축키 전체를 볼 수 있습니다.

## 입력 색공간

분석은 원본 파일을 직접 읽어 DaVinci Wide Gamut 선형으로 바꾼 뒤에 합니다. 그래서 컷마다 입력 색공간을 알아야 합니다.

- 컬러 매니지먼트(RCM) 프로젝트: Resolve 에 지정된 Input Color Space 를 그대로 씁니다.
- CST 노드 방식: API 로 CST 노드 설정을 읽을 수 없습니다. 파일 메타데이터에 단서가 있으면 그것을, 없으면 설정의 "로그 소스 기본 입력"을 씁니다. 다르면 컷을 골라 오른쪽 패널에서 바꿔 주세요(여러 컷을 한 번에 바꿀 수 있습니다).

신호만으로 확실히 가릴 수 있는 것은 로그와 Rec.709 의 구분까지입니다. S-Log3, LogC3, LogC4 는 블랙 코드값이 같아서 신호로는 구분되지 않습니다.

## 읽을 수 있는 소스

ProRes, DNxHR, XAVC(H.264/HEVC) 등 내장 FFmpeg 이 여는 포맷. FFmpeg 은 패키지 안에 들어 있어 PC 에 따로 설치할 필요가 없습니다.
R3D, BRAW, ARRIRAW, X-OCN, Cinema RAW Light 는 직접 읽지 못합니다. Resolve 에서 프록시를 연결해 두면 프록시로 분석합니다. 이미지 시퀀스는 아직 지원하지 않습니다.

## 검증한 것과 아직 못 한 것

자동 테스트 93개. Linux 와 Windows(GitHub Actions)에서 모두 통과합니다 (`pip install -r requirements-dev.txt` 뒤 `python -m pytest`).

- 전달함수 14종과 색역 13종을 colour-science 구현과 수치 대조
- 디코더: 기준 구현이 만든 Y'CbCr 을 ProRes, H.264, HEVC 로 인코딩한 뒤 읽어 코드값 대조. 프레임 단위 seek, 데이터 레벨, 601/709/2020 매트릭스
- 정답을 아는 합성 촬영본 28컷으로 분석과 매칭 전체
  - 노출과 WB: 스킨 매칭 컷의 오차 0.05 스톱 이내(출렁임 컷 0.12)
  - 블랙: 플레어를 넣은 컷의 오프셋 오차 0.0015 이내(선형, 화이트의 0.15%). 블랙이 없는 인서트는 적용하지 않는지
  - 채도: 채도 응답이 다른 카메라를 찾고 배수를 0.03 이내로 맞추는지. 메타데이터를 지워도 영상 특성으로 같은 묶음이 나오는지
- 채도 연산의 성질(중성 유지, 로그 색도가 정확히 배수만큼, 밀도 방향)과 LUT 보간 오차(평균 0.02 스톱, 99% 가 0.05 스톱 안)
- 실제 얼굴 사진으로 검출, 스킨 측정, 인물 매칭: 노출·WB·카메라 인코딩·프레이밍이 달라도 0.08 스톱 이내
- 가짜 Resolve(같은 API 형태)에 대고 스캔부터 `SetCDL`, `SetLUT` 까지, 층별 값, 잠금, 제외, 되돌리기, 재편집 뒤 값 승계, 다른 타임라인에 쓰기
- HTTP 서버와 보호 장치, UI 시나리오(헤드리스 브라우저)
- Windows 에서의 exe 빌드

0.1 은 Windows 에서 분석 도중 죽을 수 있습니다. GitHub 의 Windows 빌드에서 access violation 으로 재현됐고, 죽은 지점은 분석 스레드 여러 개가 동시에 행렬곱(BLAS)을 부르는 곳이었습니다. 0.2 에서 그 연산을 채널별 계산으로 바꾸고 BLAS 스레드를 하나로 고정한 뒤로는 재현되지 않습니다. 0.1 을 받아 두셨다면 0.2 를 쓰세요.

실제 Resolve 와 실제 촬영본이 있어야 확인할 수 있어서 아직 못 한 것. 첫 실행 때 먼저 봐 주세요.

1. 연결 자체: 이 PC 의 Python 버전으로 `fusionscript` 가 올라오는지.
2. Gamma 가 Linear 인 노드에 `SetCDL` 의 Slope 와 Offset 이 선형 게인과 선형 오프셋으로 들어가는지. 컷 하나에 컷 의도를 +1 스톱 주고, Resolve 에서 그 노드의 Gain 이 2.00 으로 찍히고 화면이 정확히 1스톱 밝아지는지 보면 됩니다. Offset 은 블랙이 적용된 컷에서 스코프의 블랙이 기준 컷과 같은 높이로 오는지 봅니다.
3. `SetLUT`: 앱이 만든 LUT 폴더를 Resolve 가 읽는지(LUT 폴더 쓰기 권한 포함), 채도 100% 가 아닌 컷의 MATCH 노드에 LUT 가 걸리는지. 다른 프로젝트에서 측정된 동작(마스터 LUT 폴더 기준 상대 경로만 받음)에 맞춰 만들었지만 직접 확인하지는 못했습니다.
4. 앱이 직접 디코딩한 값과 Resolve 내부 값의 차이. 같은 컷에서 기준 컷과 맞춘 결과를 스코프로 비교해 주세요.
5. 실제 촬영본에서의 임계값들. 스킨 샘플링, 플리커 분류, 블랙 플로어의 판정(면으로 깔린 블랙인지), 채도의 배경색 기준은 합성 영상과 사진 한 장으로만 맞춘 값입니다. 실제 MV 몇 편으로 조정이 필요합니다. 특히 블랙과 채도는 화면 내용에 따라 틀릴 수 있는 추정이라 보수적으로 걸어 두었습니다.

## 알려 둘 한계

- 블랙: 하이키 클로즈업처럼 화면에 진짜 블랙이 없는 컷은 판단할 수 없습니다. 이런 컷은 제안으로만 남습니다. 스킨으로 이어진 컷이라도 블랙이 없는데 어두운 면이 넓게 있으면 그 면을 블랙으로 볼 수 있습니다. 그런 컷은 블랙 스위치를 끄세요.
- 채도: 스킨과 배경색의 관계가 컷마다 같다고 가정합니다. 인물과 배경에 서로 다른 색 조명이 걸리는 세트에서는 맞지 않습니다. 카메라 사이의 색상(hue) 차이는 맞추지 않습니다. 채도 배수 하나만 다룹니다.
- MATCH 노드의 LUT 는 33포인트 3D LUT 이라 0 아래의 값은 잘립니다 (LUT 가 걸린 컷에서만).
- 하이라이트 롤오프 매칭은 아직 없습니다.

## 구조

```
balance/
  color/      로그 커브, 색역 행렬, 입력 색공간 레지스트리, 미리보기 변환, 채도 LUT
  media/      PyAV 디코더, 합성 촬영본(데모와 테스트)
  analysis/   프레임 측정, 플리커 분류, 얼굴과 스킨, 입력 색공간 추정, 그룹 매칭
  resolve/    Resolve API 연결, LUT 폴더, 가짜 Resolve
  core.py     엔진: 상태, 세 층 값, 작업, Resolve 쓰기
  store.py    프로젝트별 사이드카 저장소
  server.py   로컬 HTTP 서버 (127.0.0.1 전용)
  web/        UI
tools/        모델 내려받기, 미리보기 데이터 만들기
packaging/    exe 빌드 설정
tests/
```

저장 위치: 설정과 값은 `%APPDATA%\ShotBalance`, 썸네일 캐시는 `%LOCALAPPDATA%\ShotBalance\cache`. 0.1 이 만든 `Balance` 폴더가 있으면 이름을 바꿔 이어 씁니다.
창 없이 뜨는 실행(exe, `ShotBalance.bat`)의 로그는 `%APPDATA%\ShotBalance\balance.log` 에 남습니다. 시작 자체가 실패하면 오류 창이 뜹니다.
